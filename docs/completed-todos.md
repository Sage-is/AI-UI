- [x] **The page reloaded itself every 60 seconds — the reconnect was a proxy, not the fact** (2026-08-01; Alexander: _"Why does the page refresh every so often now?"_). Caused by the fix directly above. Bounding the stream to stop it blocking shutdown meant the browser reconnected every minute, and the client reloaded on ANY reconnect — so it reloaded on a timer. **The client's rule was only ever a proxy for "the server restarted"**, and it was already wrong for a dropped connection that comes back to the same process; bounding the stream just made the wrongness visible every minute instead of never. **Replaced with the fact**: every stream now opens with `event: hello` carrying a token generated at module import, and the client reloads only when that token CHANGES. Same token means the same process whatever happened to the connection. Deliberately not `env.INSTANCE_ID`, which an operator can pin through the environment — pinning it would silently disable reloading altogether. `reload_gate` grew check 6, both halves, because either alone passes on a constant: two streams from one process must AGREE, and the token must DIFFER after a reload. Proved able to fail by making the token per-connection — the gate goes red naming the symptom, _"every reconnect would reload"_. #bug

**HOLLOWING — the second migration mode (no-build strangler) (post-mortem stubbed off the board 2026-08-15 by the register pass):**

- [x] **HOLLOWING — a second migration mode, and `/home` is the first one** (2026-08-08, Alexander). The migration had one mode: replace the route, delete the Svelte file. That is right for a surface a reader reaches directly — try.sage welcome is the worked example. It is **wrong for a surface inside the app chrome**: `/home` sits in the `(app)` group, so replacing it costs the reader the sidebar, the chat list and the navigation. try.sage welcome could be replaced outright precisely because an anonymous visitor had no chrome to lose. So that class of surface was stuck — unreplaceable without a regression, and left alone it means two implementations of one view, the second of which always drifts. **Hollow it instead**: the route keeps its address and chrome, gives up its own content, and hosts the server-rendered page. `pageHost.ts` is the mechanism, `SetupDialog.svelte` is the precedent that made it small (it has hosted `/pages/admin/setup/*` in a dialog since the wizard cut over, and already solved extract-`<main>`-never-`body`, the live-`childNodes` bug that silently drops every second node, and cookie credentials). **Choosing is one question: does the reader lose anything if the SPA shell goes away?** **It costs bytes and must never be cited as a payload win** — the route boots the SPA floor and _then_ fetches a page, more than either alone; it buys reach and one implementation. **The name carries the warning**: a hollow tree is alive because only the cambium carries sap, and it also eventually comes down — record what has to be true before the hollow is deleted or it becomes permanent. For `/home` that condition is the chat core going server-rendered. Rejected names, with reasons, in the record: early retirement (parity was earned, so it is not early), partial retirement (the content is fully retired, only the frame remains), emeritus (a person metaphor here), facadism (collides with the design pattern). **Wired Sprigs™ and the WIRE vs SETTING rule (no-build strangler) (post-mortem stubbed off the board 2026-08-15 by the register pass):**

- [x] **Wired Sprigs™ shipped, and the calendar stopped being everyone's calendar** (2026-08-09).
