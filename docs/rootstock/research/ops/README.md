# ops survey: boot, installs, knobs, health, backup, image

Pinned: aa25d9b + pending 3.2.1 paths

How the running app starts, installs code, reads its settings, reports health and gets backed up, and what the image holds. Backend paths start `app/backend/sage_is_ai/`. Line counts come from `wc -l`. Anything not read in the code or run is marked `(unverified)`. `TODO.md` gains cards while this is written, so its line numbers drift; each `TODO.md` citation names its card and holds as of the last check.

## 1. Surface

- **Boot.** `main.py` is 2,584 lines. Import-time work runs first (section 2, A). Then `lifespan` (`main.py:623-766`, 144 lines) runs 16 startup steps: 8 are awaited or synchronous and can hold the first request back, 6 start background tasks, 2 are instant setup. A default install runs 4 of the 8 (section 2, B).
- **Runtime installs.** 3 call sites run `uv pip install` while the app serves: `utils/plugin.py:181`, `sprigs/vector_bootstrap.py:100`, `routers/retrieval.py:559`. Two of them build their command in `utils/runtime_install.py` (71 lines).
- **Knobs.** `config.py` (3,427 lines) builds 283 `PersistentConfig` entries in 29 path sections. A grep for `PersistentConfig(` finds 284 because it counts the class line (`config.py:162`). 282 env names are distinct; `COMFYUI_WORKFLOW` is registered twice (`config.py:2909-2919`). `config.py` and `env.py` (716 lines) read 460 distinct env names: 273 are `PersistentConfig` defaults, 187 are plain boot settings. The stored blob has 251 shape entries.
- **Health.** 2 routes in `main.py` (`:2285-2293`), 1 admin document (`routers/diagnostics.py:669`), 1 Dockerfile `HEALTHCHECK` (`Dockerfile:408`).
- **Backup and restore.** 2 HTTP routes (`routers/utils.py:132`, `:206`), 1 shell script (`restore_backup_start.sh`, 257 lines), 1 deploy step (`scripts/deploy.py:47`, file is 104 lines), 1 CLI command (`cli/ai-ui:628`, file is 894 lines), and a file-sync chain described in `docs/release-runbook.md:120-128`. The app has no scheduled database backup of its own.
- **SQLite settings.** None. No pragma, no connection event (`internal/db.py:43-46`).
- **Workers.** One uvicorn process unless `UVICORN_WORKERS` is set (`start.sh:276`, `env.py:355-362`).
- **Image.** Three stages in a 415-line `Dockerfile`. The unpacked image is 371 MB by the CHANGELOG. Twelve lines in nine files state a size or a target, and no two agree (section 2, H).

## 2. What really runs

**A. Import time.** uvicorn imports `sage_is_ai.main:app` before it starts the lifespan, so this work runs first, in this order.

1. `env.py:312-319`: rename a stray `ollama.db`, set `DATABASE_URL`.
2. `internal/db.py:52`: `legacy_db.prepare` replays the frozen DDL on an empty file.
3. `config.py:67`: `run_migrations()` runs Alembic. On a current file it reads one row. On an old file it runs data revisions; `242a2047eae0` rewrites every chat row in a Python loop (`migrations/versions/242a2047eae0_update_chat_table.py:63`).
4. `config.py:104-122` and `:269` onward: import `config.json` if present, read `CONFIG_DATA`, build the 283 `PersistentConfig` objects.
5. `config.py:732-785`: sync static files from the build's `static/`. The image has no such folder (`Dockerfile:280-281`), so it does nothing there.
6. `config.py:796-827`: when `CUSTOM_NAME` is set, up to three HTTPS fetches (10, 30 and 30 s timeouts) run before the app exists.
7. `retrieval/vector/factory.py:57-66`: build the vector client. chromadb is not in the base image, so `ImportError` leaves it `None` until a Sprig or the wizard delivers it.
8. `main.py:460-462`: `SAFE_MODE` deactivates every Function.
9. `main.py:785-789` builds `AppConfig`. `main.py:1135-1150` loads the embedding and reranking models from the local cache if present, torch included when `ml_packages` holds it.
10. `main.py:1200-1241`: two restart guards that rewrite `config` (data note, edge case 12).

**D. Knobs.**

- **Registry.** `PersistentConfig(env_name, config_path, default)` (`config.py:162-208`) takes a saved value over the env default unless `ENABLE_PERSISTENT_CONFIG` is false (`:157-159`, `:168-172`). `None` and the empty string count as unset, so a saved empty string never beats the env default.
- **In memory.** `AppConfig.__getattr__` returns the cached `.value` (`config.py:241-262`). With Redis it also reads Redis on every attribute access; without Redis, a save in one process never reaches another.
- **Whole-blob saves.** `save_to_db` replaces `data` with the process's own dict (`config.py:85-95`). `PersistentConfig.save` edits the global dict and saves all of it (`:198-208`). `save_config` swaps the global and refreshes every entry (`:139-152`). Each assignment to `app.state.config.X` is one such write (`:230-235`).
- **Registered entries, 283, by first path segment.** `rag` 70, `oauth` 39, `ui` 24, `audio` 23, `image_generation` 19, `ldap` 17, `task` 15, `try_sage` 12, `code_interpreter` 8, `code_execution` 7, `auth` 6, `magic_link_login` 6, `analytics` 5, `bridges` 5, `openai` 4, `onedrive` 4, `google_drive` 3, `ollama` 3, `evaluation` 2, `file` 2, and one each for `direct`, `models`, `notes`, `privacy`, `spaces`, `tool_server`, `user`, `webhook_url`, `webui`.
- **Plain env names, 187.** `env.py` holds 87, grouped by its section comments: WebSocket 12, OpenTelemetry 10, secret key 8, try.sage 8, auth 6, Redis 5, audit log 5, and 33 more. `config.py` holds 102 more that no `PersistentConfig` wraps: vector databases 43 (32 belong to the five stores the plan cuts: Milvus 8, Elasticsearch 7, Qdrant 6, Pinecone 6, OpenSearch 5), `WEBUI` 30, document parsing 11, and 18 others. Boot-only values such as `DATABASE_URL`, `REDIS_URL`, `WEBUI_SECRET_KEY`, `UVICORN_WORKERS` and `ENABLE_TRY_SAGE` cannot be set from the database (`docs/product-stack.md:126`).
- **Saved against registered.** The 2026-07-12 blob has 251 shape entries. 207 are read by a registered entry. 44 are read by none: 37 under `rag.web.search`, 3 under `task`, `channels.enable`, `version`, `rag.embedding_openai_batch_size`, and the census's bucket of 4 long-named `rag` keys. **E. Health.**

- **`GET /health`** returns `{"status": True}` and checks nothing (`main.py:2285-2287`). It proves the process answers. The Dockerfile `HEALTHCHECK` calls it through `localhttp --require-true status` (`Dockerfile:408`) with Docker's defaults: 30 s interval, 30 s timeout, 3 retries, no start period (unverified: Docker's documented defaults). uvicorn's access log drops `/health` lines (`config.py:33-39`). `scripts/deploy.py:76`, `scripts/manual-check.sh:134-137` and `scripts/wizard-smoke.sh:113` all treat a 200 here as "up".
- **`GET /health/db`** runs `SELECT 1` on the scoped session (`main.py:2290-2293`). Only the untracked `scripts/kb-probe.py:66` calls it.
- **`GET /api/v1/diagnostics/health`** (admin only, `routers/diagnostics.py:669-689`, mounted at `main.py:1589`) returns six sections: deployment shape, boot probes, endpoints, boot status, static assets, browser headers. Boot status checks the data directory is writable (`:274`), the secret key (`:356`), the Alembic head (`:412`) and the dev reloader (`:471`). It reports no journal mode, free disk, backup age, Sprig owner or orphaned vector collections.
- **`GET /api/config`** carries the version that `scripts/deploy.py:38-44` and `cr-deploy --verify` compare after a rollout.
- A Sprig child's own `/health` is stricter than the app's: the Whisper server answers 503 until its model loads (`scripts/build-sprig-whisper.sh:27`).

**F. Backup and restore.** Seven mechanisms. None takes a consistent snapshot of the database.

1. **Download.** `GET /api/v1/utils/db/download` (`routers/utils.py:132-150`) is admin only, on unless `ENABLE_ADMIN_EXPORT` is false (default on, `config.py:1478`), SQLite only. It returns `FileResponse(engine.url.database)`: the live file, read with no checkpoint, no lock and no `VACUUM INTO`. A write during the transfer can tear the copy (`docs/release-runbook.md:128` says the same of the synced copy).
2. **Deploy backup.** `scripts/deploy.py:47-62` pulls that route with the app's admin key, holds the whole body in memory (timeout 600 s, `:54-55`), checks only the 16-byte header `SQLite format 3\x00` (`:19`, `:56-58`) and writes `~/Backups/ai-ui/<app>/<date>-<version>.db` at mode 600. It runs for apps marked `backup` in `deploy/instances.toml`: 1 of 2. No backup, no deploy (`:48-52`).
3. **Restore on first run.** `POST /api/v1/utils/db/restore` (`routers/utils.py:206-363`) has no auth dependency and refuses once any `user` row exists (`:216-220`). It takes a raw `.db` or a `.zip` up to `BACKUP_RESTORE_MAX_SIZE_MB`, 512 by default (`env.py:322`). It checks `PRAGMA integrity_check` and at least one user (`:153-164`), disposes the engine, copies the old file to `webui_pre_restore.db` and moves the new one over `webui.db` (`:279-280`, `:325-326`), then runs `legacy_db.prepare` and Alembic (`:183-203`, `:345`). A failure moves the old file back (`:355-356`). A zip may add `uploads/*` and nothing else (`:174-180`, `:328-339`): no `vector_db/`, no Sprig state, no secret-key file.
4. **In-container rclone.** `restore_backup_start.sh` is the entrypoint (`Dockerfile:415`, 257 lines). With `AUTO_BACKUP=true` (default off, `:238`) a loop runs `rclone copy /app/backend/data/ <remote>:/<path>` on a three-field schedule (script default `0 5 *`, `:191`; the Dockerfile sets `0 2 *`, `Dockerfile:355`). `AUTO_RESTORE=true` copies the remote over the live folder before the app starts (`:64-75`, `:124-130`, `:180`). rclone is not in the image, so the function logs "backup skipped" until the `backup-rclone` Sprig is grafted (`:53-56`). `setup_rclone` prints the generated rclone config, secrets included, to the container log (`:46-48`).
5. **CLI update.** `cmd_update` (`cli/ai-ui:628-647`) pulls the image, stops and removes the container, then `cmd_start` removes any container with `docker rm -f` and runs the new image on the same volume (`:299-330`). No backup and no rehearsal. `ai-ui migrate` tars the whole volume through a throw-away alpine container (`cli/lib/sage-runtime.sh:848-886`).
6. **Production chain.** The production app's data folder is synced by Syncthing across three nodes and an office Mac, and Backblaze copies the Mac (`docs/release-runbook.md:120-128`, `TODO.md:81,88-89`). The nightly `sqlite3 .backup` into that folder is an open card (card "SQLite over Syncthing", `TODO.md:88`; first task `backup`, `:200`).
7. **Test snapshots.** `Makefile:467` copies one main file into a temp folder for `test_db_upgrade`. `scripts/smoke/upgrade-gate.sh:37-38` tars a whole snapshot folder, minus `cache/`, into a fresh volume. Both read whatever `/db/download` once returned.

**G. SQLite settings and workers.**

- **No settings.** `create_engine(url, connect_args={"check_same_thread": False})` (`internal/db.py:44-46`) sets no pragma, no connect event and no `timeout`. The engine runs the journal mode stored in the file (`delete` in both snapshots) with `synchronous` full. Python's own busy timeout still applies: 5 s (checked here, `PRAGMA busy_timeout` returns 5000 on CPython 3.12.3; the image's 3.11 has the same default). So "no `busy_timeout`" is not quite true; the timeout is 5 s, not the 15 s the plan wants. SQLAlchemy 2.0.38 (`app/backend/requirements.txt:41`) should give a file database a `QueuePool` of 5 plus 10 overflow connections (unverified). Foreign keys stay off.
- **Who contends.** Sync model code runs in anyio's thread pool, 40 threads unless `THREAD_POOL_SIZE` changes it (`config.py:1507-1516`, `main.py:656-658`). Every authenticated request writes `user.last_active_at` (data note, edge case 9), and a streamed answer rewrites the whole chat JSON at each save point, once per chunk when `ENABLE_REALTIME_CHAT_SAVE` is on (default off, `env.py:328`; `utils/middleware.py:1924-1932`). A reader that waits past 5 s raises, `get_user_by_id` swallows it into `None` (`models/users.py:151-157`), and the caller answers 401 "session expired" (card "A busy database reads as session expired", `TODO.md:1392`).
- **One worker is a rule.** `start.sh:276` passes `--workers "${UVICORN_WORKERS:-1}"`; `env.py:355-362` parses it. The supervisor takes a non-blocking `flock` on `DATA_DIR/sage-is/sprigs/.reconcile.lock`, so only one worker spawns Sprig children (`sprigs/supervisor.py:991-1010`); a second worker logs a warning and its grafted view can differ (`:827-847`). `PersistentConfig` copies are per worker unless Redis is set (`config.py:211-262`), Socket.IO needs `WEBSOCKET_MANAGER` for fan-out (`env.py:449-462`), and every in-process cache is duplicated (card "Redis/valkey + multi-worker", `TODO.md:875-877`, which cites `start.sh:233`; the line is now 276). The dev reloader forces one worker (`start.sh:252-274`).

**I. What breaks if WAL is switched on today.** `PRAGMA journal_mode=WAL` is stored in the file, so it covers the old app and any older image with no code change. Commits then land in `webui.db-wal` and reach `webui.db` at a checkpoint (SQLite's default is every 1,000 pages, about 4 MB). Every tool that copies `webui.db` alone then copies an older state, or a torn one.

1. **`/db/download`** returns the main file only (`routers/utils.py:132-150`). Pages still in the `-wal` are missing, and a checkpoint during the transfer tears the rest.
2. **`scripts/deploy.py`** checks the 16-byte header only (`:19`, `:56-58`), so a stale or torn copy passes and is filed as the rollback point. `docs/release-runbook.md:128` calls that download "the clean restore point". It would stop being one.
3. **`rclone copy`** of the data folder (`restore_backup_start.sh:57-60`) copies `webui.db`, `-wal` and `-shm` at different instants. `-shm` is a shared-memory index that is rebuilt, never restored. `AUTO_RESTORE` (`:64-75`, `:180`) would copy all three over a live folder.
4. **Syncthing** on the production app (`TODO.md:81,88`) syncs each file on its own clock, so a replica can hold a main file and a `-wal` from different moments. The board plans to ignore `-wal` and `-shm` and sync a nightly `sqlite3 .backup` instead (`TODO.md:88`). That card is open, so treat the ignores as not set. Until both exist, WAL makes the "replicas can sync torn" risk worse. After they exist, a replica holds a consistent but older file, never the live one.
5. **`/db/restore`** moves a new file over `webui.db` (`routers/utils.py:279-280`, `:325-326`). It calls `engine.dispose()` first, which checkpoints and removes the `-wal` on the last close, so the normal path should hold. A stale `-wal` left by a crash, or held open by a second process, beside the replaced file is the case to test. `webui_pre_restore.db` is a copy of the main file alone.
6. **Test inputs.** `Makefile:467`, `scripts/smoke/upgrade-gate.sh:37-38` and the census (`mode=ro&immutable=1`, which should skip a `-wal`; unverified) read the main file. A snapshot copied from a WAL file with no checkpoint loses data without an error. Take snapshots with `VACUUM INTO` or `.backup`.
7. **Filesystems.** WAL needs shared memory and does not work over network mounts. The `ai-ui` named volume is local to the VM (`cli/ai-ui:15-16`, `:319-324`). A bind mount through a macOS sharing layer, an NFS export or a Syncthing-owned folder needs a test first (unverified).
8. **Shutdown.** `restore_backup_start.sh:160-177` signals uvicorn and exits at once, with no `wait`, so the container can end before the last connection closes. The next open recovers from the `-wal`, so nothing is lost; a volume copy taken in that window is short of the last commits (inferred from the script, not run).

What WAL buys is that readers stop waiting on writers, the likely cause of the 401s in the "busy database" card (`TODO.md:1392`). The plan's order is right: a `VACUUM INTO` download and the Syncthing ignores first, WAL second.

## 3. Edge cases worth keeping

1. **The port opens late.** The lifespan finishes before uvicorn binds (`main.py:623-755`), so one slow awaited step makes the app unreachable, not degraded. Step 13 alone costs up to the model-list timeout per dead provider (`utils/models.py:92-97`). The plan's 2 s start has to take steps 4, 6, 13 and 15 out of the path.
2. **An install can freeze every request.** `install_frontmatter_requirements` is a blocking `subprocess.check_call` with no timeout (`utils/plugin.py:186`). It is reached from async code the first time a process loads a Function (`utils/models.py:315,326`, `functions.py:249`), so one slow package index stalls the event loop.
3. **Health says "up" while search is dead.** `/health` is constant (`main.py:2285-2287`). On the production app the vector client was `None`, queries answered 200 with no hits and adds answered 400 (`TODO.md:149-150`), and diagnostics called the mock embedding `ok` (`TODO.md:152`). A `doctor` that says "unknown" is not "ok" is a requirement, not polish.
4. **Clearing a setting does not survive a restart.** A saved empty string loses to the env default when the entry is built (`config.py:168`), yet a live `update()` applies it (`config.py:192-196`). The running process and the next boot disagree. The Rootstock registry must define "unset" once.
5. **Settings are cached per process and saved whole** (data note, edge cases 11 and 12). The cost is 197 assignment sites outside `main.py`, each a full-blob write, plus the boot rewrites by the supervisor and the restart guards. Without Redis a second worker never sees a save.
6. **Secrets travel in clear.** `setup_rclone` prints the generated rclone config to the container log (`restore_backup_start.sh:46-48`). `rclone copy` of the data folder carries `.webui_secret_key`, `webui.db` with `config` and `privacy_map`, and the vector store (`:57-60`). `/db/download` carries the same database.
7. **Shutdown races teardown.** `cleanup` signals uvicorn and exits (`restore_backup_start.sh:160-177`), `ai-ui update` stops with Docker's default 10 s (`cli/ai-ui:332-337`), and `ai-ui start` over a live container uses `docker rm -f`, a kill (`cli/ai-ui:316`). The lifespan shutdown (`main.py:757-766`) may never finish.
8. **A zip restore brings rows, not vectors.** It extracts `webui.db` and `uploads/` only (`routers/utils.py:174-180`). `vector_db/`, Sprig state (`DATA_DIR/sage-is/sprigs/state.json`, `sprigs/supervisor.py:932-936`) and the key file stay behind. The production vector store already holds 0 collections against 19 knowledge bases, with 654 orphan HNSW folders (`TODO.md:151`), so a raw backup of `vector_db/` is not a backup of search.
9. **First-run restore has no auth.** `POST /db/restore` carries no dependency and gates only on `Users.get_num_users() != 0` (`routers/utils.py:206-220`). Whoever reaches a fresh instance first can load a database of their choosing and become its admin. If the Rootstock keeps restore-at-onboarding, it needs a bootstrap secret.
10. **The deploy backup trusts 16 bytes.** `scripts/deploy.py:56-58` accepts any body that starts with the SQLite header, after holding it all in memory (`:54-55`). A truncated download passes. The Rootstock backup should come from `VACUUM INTO`, then `PRAGMA integrity_check`, row counts and a size band.
11. **A long call dies at 100 s.** Cloudflare cuts a request there, and re-index is one synchronous request (`TODO.md:156`). The wizard avoids this with a background task and a status dict (`routers/retrieval.py:464-677`). Every long Rootstock operation needs a job record, not a held connection.
12. **Stale health rows never expire.** The diagnostics registry persists in `DATA_DIR/diagnostics.json` (`diagnostics/health_registry.py:204`) and keeps dead loopback Sprig ports: 20 on production (`TODO.md:153`). A Sprig gets a new port every boot, so the rows only grow.
13. **A Function can replace a base package.** Function installs run `uv pip install --system --break-system-packages` into the image's own site-packages (`utils/runtime_install.py:54-62`). The wizard once shadowed the system `bcrypt` and broke login (`CHANGELOG.md:396-397`); the `ml_packages` order fixed that path, but Function requirements still share the base tree.
14. **The proxy is trusted blindly.** uvicorn runs with `--forwarded-allow-ips '*'` (`start.sh:276`), and the container runs as root unless built with a UID (`Dockerfile:17-18`, `:138-139`). Behind the cluster proxy that holds; on a box without one, any peer can forge `X-Forwarded-*`.

## 5. Rootstock equivalent

- **Boot.** `python -m sage_is_ai.rootstock migrate` runs before uvicorn: legacy Alembic, then WAL on, then Django migrations (plan). The Rootstock lifespan keeps only instant steps (1 and 7). The four slow steps move out: the model list is built lazily and cached per connection revision (step 13), the Sprig reconcile runs in the background and `doctor` reports "reconciling" (step 15), Function installs happen at graft time (step 4), and prefix migrations are deleted (step 6). **The plan's 2 s start cannot hold before the last cutover step.** The seam imports the old `main` and boots it "exactly as today" (plan, The seam), so steps 4, 6, 13 and 15 still run in front of every request until `main.py` is deleted. Either the F0 legacy fixes also move those four steps, or the `rs_boot` gate is scoped to the last step.
- **Installs.** None at run time. A Function's requirements install into that Sprig's own directory when it is grafted, never into the base site-packages (edge case 13). `uv` leaves the image with the install code (section 4).
- **Knobs.** One `Setting` table, at most 80 entries. What the plan cuts or moves to Sprigs takes 88 of the 283 registered entries: `ldap` 17 and `evaluation` 2 (cut); `audio` 23, `image_generation` 19, `code_interpreter` 8, `code_execution` 7, `bridges` 5, `onedrive` 4, `google_drive` 3 (Sprigs). Two blocks the plan does not name, `analytics` 5 and `try_sage` 12 (legacy until the trial moves), bring the total to 105. That leaves 178: `rag` 70, `oauth` 39, `ui` 24, `task` 15, `auth` 6, `magic_link_login` 6, `openai` 4, `ollama` 3, `file` 2 and nine singletons. Reaching 80 needs 98 more cuts, mostly in `rag` (document-parsing engines), `oauth` (provider claims) and `ui`. The census cannot say which of them anyone changed: as built it records booleans and shapes, and the plan's "non-default config paths as `path: changed`" is not in `census.py` (`shape()` returns booleans and descriptions only). Extend it before the table is cut.
- **Health.** `/api/v2/doctor` (plan) reports journal mode, schema head, route owners, Sprig owner, backup age, free disk and orphaned vector collections, with "unknown" distinct from "ok". `/health` keeps its name for the `HEALTHCHECK` and for `cr-deploy --health`, answers 503 until the schema head matches and the database opens, and the `HEALTHCHECK` gains a `--start-period`. `utils/localhttp.py` stays the client.
- **Backup and restore.** A `VACUUM INTO` job writes a dated file into `DATA_DIR/backups/`, before each migration and on a schedule. `/db/download` streams the newest snapshot, not the live file. `scripts/deploy.py` then runs `PRAGMA integrity_check` and compares row counts instead of reading 16 bytes. `ai-ui update` takes a dated snapshot and boots the new image on a copy first (plan). Syncthing syncs `backups/` and ignores `webui.db`, `-wal` and `-shm`. Restore becomes a CLI command that runs while the app is stopped, deletes any `-wal` and `-shm`, and restores `uploads/` and Sprig state with the database. If first-run restore over HTTP stays, it takes a bootstrap secret (edge case 9).
- **SQLite.** WAL, `busy_timeout=15000`, `synchronous=NORMAL` and `IMMEDIATE` transactions on the Django side; `timeout=15` on the legacy engine (plan). Order of work: the snapshot download and the Syncthing ignores first, WAL second (section 2, I). One worker and one writer stay; the supervisor lock stays with them.
- **Image.** A measured `image_budget` gate records unpacked and compressed size per architecture. `docs/rootstock/design.md` holds the one number; the stale lines in the table in section 2, H are fixed or deleted in the same commit. The target is 150 MB at the end of the cutover.
