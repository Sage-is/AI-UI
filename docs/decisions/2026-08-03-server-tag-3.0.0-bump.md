## Incident during the edit, repaired

macOS BSD `sed -i` **broke the three-way hardlink chain** (AI-UI / homebrew-apps / Sage.Education-docs): it writes a temp file and renames it over the target, replacing the inode. Link count fell 3 → 1.

Repair: the two sibling copies still shared the old inode. The bump was rewritten into that inode via content redirect (`sed … file > tmp && cat tmp > file` truncates and writes in place), then the AI-UI copy was re-linked with `ln -f`. Verified after: all three paths on inode `377143745`, link count 3, identical content.

**Standing correction:** the global instruction "use `sed -i` to preserve the inode" is wrong on macOS. The redirect method above is the safe in-place edit. TODO.md's card text now carries the warning.
